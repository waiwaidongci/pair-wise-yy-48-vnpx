# 消防报警系统联动逻辑配置与调试审阅平台

面向消防工程师、调试人员和审阅人的联动逻辑工作台，支持设备台账、因果矩阵、互锁/延时/优先级配置、矩阵校验、依赖图、版本差异、联调清单和签字锁定。

## 技术栈

Vue 3 + Vuetify + Pinia + Vue Router + Apollo Client + GraphQL + Vite + TypeScript

## 本地运行

```bash
npm install
npm run dev
```

访问 `http://localhost:62048`。

## 联动批次核算（/batch）

在规则冲突校验之外，增加同楼层多台设备同时动作时的供电余量核算：

- 选定报警点与各楼层供电容量后，按规则延时、优先级（P1>P2>P3）和互锁反馈顺序排出动作队列，按楼层分批核算同时动作负荷。
- 容量不够时低优先级非关键动作先往后顺延（每步 5s），其互锁后继同步顺延；**排烟风机、防火卷帘、疏散广播任何情况下照常启动**，超额批次整批标出缺口，核算结论不假报“已满足”。
- 队列带失效签名：设备换层、楼层容量或规则（延时/优先级/互锁/启停）一变，已有队列立即失效并按新现场重算，已完成动作保留为现场事实且不重做。
- 写盘采用“推进前断点 → 执行 → 已确认”协议：写盘失败时暂停推进、不新增完成态；刷新恢复后从断点继续，已完成动作不重做。可用页面上的“模拟写盘故障”开关演练。
- 两名调试员几乎同时提交同一层容量时，只采用更早的一份；后到者的现场值保留在仲裁记录中并标明冲突，由调试员裁决采用哪一份。

## 测试

```bash
npm test        # 调度算法 + 队列 store 场景（容量顺延/关键设备/互锁/失效/断点/并发仲裁）
npm run build   # 类型检查与生产构建
```

## 核心工作流

- 按楼层分区维护探测器、模块和消防设备，建立触发到动作的因果矩阵。
- 配置延时、互锁、优先级和抑制条件，并批量启停或修改矩阵规则。
- 自动发现遗漏、重复、自相矛盾和跨区冲突，在依赖图中定位问题。
- 比较专业提交版本并部分接受变更，完成联调清单后签字锁定交付包。
